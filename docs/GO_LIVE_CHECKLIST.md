# Go-live চেকলিস্ট — Meta অনুমোদনের পরে

তারিখ: ২০২৬-১১-১৬। এই তালিকা Meta App Review শেষ হওয়ার পর ব্যবহারের জন্য। প্রতিটা ধাপ আগের ধাপ সফল হলে তবেই।

> **নিয়ম ১:** Meta review চলাকালীন ভিপিএস-এর চালু সংস্করণে হাত দেওয়া যাবে না। রিভিউয়াররা সেটা দিয়েই লগইন ও webhook পরীক্ষা করেন।
> **নিয়ম ২:** আসল নম্বর/পেজ যুক্ত করার আগে ও পরে প্রতিটা ধাপে bot বন্ধ। আসল নম্বর কখনো `/register` বা সাধারণ "Add phone number" দিয়ে নয়, শুধু Coexistence Embedded Signup।
> **নিয়ম ৩:** ধাপ ১৪ (আসল নম্বর/পেজ) আপনার স্পষ্ট অনুমতি ছাড়া শুরু হবে না।

**জানা সীমা:** রিপোতে Dockerfile, Caddyfile বা backup স্ক্রিপ্ট নেই (শুধু `docker-compose.yml` আছে ডাটাবেজের জন্য)। ভিপিএস-এ আজকের সংস্করণ কীভাবে চলছে (কোন কমান্ডে, কোন ফোল্ডারে), সেটা আমি জানি না। ধাপ ২-এর কমান্ডগুলো তাই আপনার সেটআপ অনুযায়ী মিলিয়ে নিতে হবে।

- [ ] ভিপিএস-এর সংস্করণ, `.env`, webhook URL, লগইন অ্যাকাউন্ট কিছুই বদলাবেন না।
- [ ] Meta-র দিকের বাকি কাজ: Portfolio-র ১ জনের 2FA, "Review needed" থাকা Page, App Review-এর প্রশ্নের উত্তর।
- [ ] এই সময়ে যা করা যায়: লোকাল ডেভ, টেস্ট, নতুন ফিচার। কিছুই ভিপিএস-এ তুলবেন না।

## ধাপ ১ — অনুমোদনের পরদিনই: প্রস্তুতি

- [ ] **Gemini key বাতিল:** আগে চ্যাটে যে Google AI Studio key পেস্ট হয়েছিল, সেটা Google AI Studio-তে মুছে নতুন key নিন। নতুন key কোথাও চ্যাটে পাঠাবেন না; শুধু অ্যাপের Configuration পেজে বসাবেন।
- [ ] ডেভ ইউজার (`admin@dev.local`, `agent@dev.local`, পাসওয়ার্ড `dev-pass-12345`) ভিপিএস-এ আছে কি না দেখুন; থাকলে আসল অ্যাডমিন বানিয়ে এগুলো মুছুন।
- [ ] আসল অ্যাডমিন: `npx tsx scripts/create-user.ts --email … --name "…" --role admin` (পাসওয়ার্ড `CRM_USER_PASSWORD` env থেকে, নইলে র‍্যান্ডম)।
- [ ] ভিপিএস-এর ডিস্কে জায়গা আছে কি না দেখুন (মিডিয়া ফোল্ডারের জন্য)।

## ধাপ ২ — নতুন সংস্করণ তোলা (ভিপিএস)

1. **ব্যাকআপ আগে:** ডাটাবেজ dump (`pg_dump`) ও VPS snapshot। ব্যাকআপ ছাড়া মাইগ্রেশন নয়।
2. **কোড তোলা:** `git pull` (বা আপনার পদ্ধতি), `npm ci`, `npm run build`।
3. **`.env` মিলিয়ে নেওয়া** (নিচের তালিকা)।
4. **মাইগ্রেশন:** `npm run db:migrate` (সংখ্যা অনুযায়ী `0007`–`0013` পর্যন্ত যা বাকি আছে)। মাইগ্রেশন ছাড়া নতুন কোড চালালে ইনবক্স ভেঙে যায় (`relation "lifecycle_stages" does not exist`; ডেভে এটাই ঘটেছিল)।
5. **মিডিয়া ফোল্ডার:** `MEDIA_DIR` একটা স্থায়ী ভলিউমে (কনটেইনার মুছলেও থাকে এমন জায়গায়) রাখুন।
6. **চালু ও যাচাই:** অ্যাপ রিস্টার্ট; লগে ত্রুটি নেই দেখুন। background worker একবারই চালু হয় (`instrumentation.ts`), একাধিক instance চালালেও নিরাপদ।
7. **ধোঁয়া-পরীক্ষা (smoke test):** লগইন, `/dashboard`, `/inbox` (খালি হলেও ত্রুটি নেই), `/settings/stages`, `/settings/configuration`, `/api/webhooks/whatsapp`-এ GET verify।

**`.env`-এ যা থাকতেই হবে** (মান `.env.example` দেখুন; গোপন মান কখনো git-এ নয়):
`DATABASE_URL`, `APP_URL=https://crm.saimum.org`, `AUTH_SECRET`, `ENCRYPTION_KEY` (৬৪ হেক্স), `META_APP_ID`, `META_APP_SECRET` (খালি থাকলে সব webhook বাতিল হবে), `META_GRAPH_VERSION`, `META_WEBHOOK_VERIFY_TOKEN`, `META_ES_CONFIG_ID`, `MEDIA_DIR`, `OFFICE_TZ/OPEN/CLOSE`।
**শুরুতে বন্ধ রাখুন:** `ALLOW_REAL_CHANNEL_CONNECT=false`, `ALLOW_BROADCAST=false`।
AI key `.env`-এ না দিয়ে Configuration পেজ থেকে দিলে এনক্রিপ্ট হয়ে ডাটাবেজে যায়।

**ফেরার পথ (rollback):** আগের কোড-সংস্করণ চালু করা + dump থেকে ডাটাবেজ ফেরানো। মাইগ্রেশন শুধু টেবিল/কলাম যোগ করে, কিছু মোছে না, তবে পুরনো কোড নতুন কলাম ছাড়া চললেও নতুন ডেটা হারাতে পারে; তাই ব্যাকআপ জরুরি।

## ধাপ ৩ — Meta টেস্ট নম্বর/পেজ দিয়ে end-to-end (আসল গ্রাহক নয়)

শুধু Meta-র টেস্ট নম্বর ও একটা টেস্ট পেজ। আসল নম্বর নয়।

- [ ] Meta webhook URL বসানো: `https://crm.saimum.org/api/webhooks/whatsapp` ও `/api/webhooks/messenger`; verify token `.env`-এর সাথে মেলানো।
- [ ] Messenger-এ `messages`, `message_echoes`, `messaging_postbacks` সাবস্ক্রাইব।
- [ ] টেস্ট নম্বর থেকে মেসেজ পাঠান → ইনবক্সে আসা, `X-Hub-Signature-256` যাচাই, একই মেসেজ দুবার এলে একবারই সেভ।
- [ ] ইনবক্স থেকে উত্তর পাঠান → টেস্ট নম্বরে পৌঁছানো, স্ট্যাটাস sent → delivered → read।
- [ ] ২৪ ঘণ্টার বাইরে: WhatsApp-এ template, Messenger-এ মানুষের `HUMAN_AGENT` (৭ দিন)।
- [ ] ছবি/ভয়েস পাঠান → ডাউনলোড ও দেখা (মিডিয়া ডাউনলোড একবারও আসল API-তে চলেনি)।
- [ ] Template জমা → Meta অনুমোদন → `message_template_status_update` webhook-এ অবস্থা বদলানো। **CLAUDE.md-র "অযাচাইকৃত" তালিকা** (template তালিকার paging, status webhook-এর ফিল্ড, error কোড) এখানে মিলিয়ে ভুল পেলে parser ঠিক করুন।
- [ ] টেস্ট নম্বরে ছোট broadcast (শুধু সম্মতিপ্রাপ্ত টেস্ট কন্টাক্ট)।
- [ ] AI: আসল key বসিয়ে বাংলা প্রশ্নের উত্তর, handoff, AI খসড়া বোতাম। **ডিফল্ট মডেলের নাম (`claude-haiku-5-5` / `gpt-4o-mini`) আসল API-তে যাচাই করুন।**
- [ ] Facebook Login দিয়ে টেস্ট পেজ সংযুক্ত; Messenger কাস্টমারের নাম Graph থেকে আনা (এখন PSID দেখায়)।
- [ ] যা ভুল ধরা পড়ে, `tests/fixtures/`-এ আসল payload রেখে parser ঠিক ও টেস্ট যোগ।

## ধাপ ৪ — আসল নম্বর ও পেজ (আপনার অনুমতি নিয়ে)

**আগে:** ধাপ ৩ পুরোপুরি সফল; নতুন ব্যাকআপ; আপনার স্পষ্ট "হ্যাঁ"।

- [ ] `ALLOW_REAL_CHANNEL_CONNECT=true` (শুধু এই মুহূর্তের জন্য)।
- [ ] WhatsApp: Business App-এ ফোন চালু রেখে Coexistence Embedded Signup। নম্বর, অ্যাপ, কন্টাক্ট ও গ্রুপ অক্ষত থাকা যাচাই।
- [ ] history ও contact sync আসছে কি না দেখুন (আসল payload ধরে fixture বদলান)।
- [ ] Facebook Pages একটা একটা করে (Saimum Shilpigosthi, Saimum KIDS…)।
- [ ] সংযোগের পর `ALLOW_REAL_CHANNEL_CONNECT=false` আবার।
- [ ] নতুন আসল চ্যানেল **bot বন্ধ** অবস্থায় শুরু (ডিফল্ট)। আসল webhook ঠিকঠাক আসছে কি না, মানুষ উত্তর দিলে ফোন/পেজ ইনবক্সের echo ঠিকমতো আসছে কি না দেখুন।

## ধাপ ৫ — bot ধাপে ধাপে চালু

| --- | --- | --- |
| প্রথম ১–২ সপ্তাহ | **বন্ধ** | শুধু ইনবক্স; সব উত্তর মানুষ |

## জানা ঝুঁকি (চালুর আগে মাথায় রাখুন)

- **আসল Meta-তে প্রথম পরীক্ষা**: কোড ডক ও ধারণা অনুযায়ী লেখা; প্রথম আসল পরীক্ষায় কিছু ভুল বেরোবে। তাই ধাপ ৩ ছাড়া সোজা ধাপ ৪ নয়।
- **WhatsApp-এ ২৪ ঘণ্টার পরে** ইনবক্স থেকে ব্যক্তিগতভাবে template পাঠানো আছে, কিন্তু আসল Meta-তে পরীক্ষিত নয়।
- **একটাই Node প্রসেস ধরা**: real-time (SSE) ও লগইন-ব্যর্থতার সীমা মেমরিতে। একাধিক instance চালালে Postgres LISTEN/NOTIFY ও DB-ভিত্তিক সীমায় সরাতে হবে।
- **ফোন বদলালে/নম্বর পোর্ট হলে** Coexistence সংযোগ আবার যাচাই করতে হতে পারে।
